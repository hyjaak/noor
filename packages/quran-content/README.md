# Quran content dataset

Generated by [scripts/generate-quran-content.mjs](../../scripts/generate-quran-content.mjs)
from two npm packages. Regenerate with:

```
node scripts/generate-quran-content.mjs
```

## `quran.json`

All 114 surahs / 6236 ayahs. For each ayah: Uthmani Arabic text, English
transliteration, English translation (Sahih International), mushaf page
number, juz number, and a Mishary Alafasy recitation audio URL
(cdn.islamic.network, indexed by global ayah id).

- Source: [`quran-json`](https://github.com/risan/quran-json) (Uthmani text
  from The Noble Qur'an Encyclopedia; transliteration and translation from
  Tanzil.net). License: CC-BY-SA 4.0.

## `pages.json`

The standard 604-page Madani mushaf layout (Hafs riwaya): for each page
number, the first/last surah:ayah on that page and the full ordered list of
verse keys it contains.

- Source: [`quran-meta`](https://github.com/quran-center/quran-meta).

No live third-party API calls happen at runtime -- both files are static and
bundled with the app.

## `word-timing.json`

Generated by [scripts/generate-word-timing.mjs](../../scripts/generate-word-timing.mjs)
from `source/alafasy-word-timing.raw.json`. Regenerate with:

```
node scripts/generate-word-timing.mjs
```

Real per-word audio start/end timestamps (milliseconds) for the Mishary
Alafasy 128kbps recitation -- the same recording our `audio` URLs
(cdn.islamic.network/quran/audio/128/ar.alafasy) already point at. Keyed by
`"surah:ayah"`, each entry is an ordered list of `{ i, t, s, e }` (word index,
word text, start ms, end ms).

- Source: [`cpfair/quran-align`](https://github.com/cpfair/quran-align)
  (`release-2016-11-24`, `Alafasy_128kbps.json`), machine-aligned via CMU
  Sphinx forced alignment. License: CC-BY 4.0 -- see
  `source/quran-align-LICENSE.txt`.
- Coverage: 6217 of 6236 ayahs. The 19 excluded ayahs are ones where the
  released segment word-ranges didn't exactly cover our Arabic text word-for-
  word (see the generation script's validation) -- rather than guess an
  alignment, those ayahs are simply absent from this file, and the reader
  falls back to ayah-level sync for them.
- No word-level transliteration data was found from a real, verifiably
  word-aligned source (only ayah-level transliteration exists in this
  dataset, from `quran-json`/Phase 10a) -- so transliteration stays ayah-level
  and is synced at the ayah level, not the word level. See Phase 12 notes.
